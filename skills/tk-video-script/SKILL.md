# TK Video Script

这个 skill 用来回答一个核心问题：**这个 TikTok 产品应该怎么拍视频、怎么写脚本，才更贴近真实销售和内容信号？**

它不是凭空写广告文案，而是先看真实的商品、视频、达人、评论和成交渠道证据，再生成可拍摄、可发布、可测试的脚本。

## 数据规则

运行前读取 `references/data-source.md` 和 `references/data-capabilities.md`，发现当前可用工具并映射逻辑能力。没有兼容数据源时请求配置 MCP 或导入离线文件。

不要编造趋势、评论、卖点、价格、销量、达人表现或标签。缺少证据时要标注“缺少数据”，脚本里只能使用已确认的产品事实，创意假设要明确标注。

不要要求用户把 Key 粘贴进聊天，也不要把供应商工具名写成通用字段。

## 适用场景

- 用户给一个 TikTok 商品，希望生成短视频脚本。
- 用户给关键词或品类，希望生成多个内容角度。
- 用户想把商品卖点转成美国、英国、东南亚等本地化表达。
- 用户想复盘竞品视频，提炼可模仿的脚本结构。
- 用户想给达人写拍摄 brief。
- 用户想做 7 天内容测试，比较不同 hook、CTA、视频长度。

## 输入信息

最少需要：

- 产品线索：`commodityId`、TikTok 商品链接、商品名、关键词、图片线索或类目。
- 市场和语言：用户不说时默认美国 / 英文。
- 目标：带货、产品教育、达人合作、品牌曝光、测试内容角度。

可选信息：

- 目标人群、价格带、语气、视频时长、达人风格、禁用表述、品牌口吻、脚本数量。

如果用户只给产品想法，先做 configured data source 商品和视频扫描，再推断最合适的内容方向，不要一开始就问一大堆创意偏好。

## 分析流程

1. 确认产品事实。
   - 用 `tiktok.product_search` 找候选商品。
   - 用 `tiktok.product_detail` 看标题、类目、价格、图片/链接、评分、店铺、达人数、视频数、销量、销售额。
   - 用 `tiktok.sales_history` 判断商品动量或季节性。
   - 用 `tiktok.channel_mix` 判断销售主要来自商品卡、店铺自营还是达人。
   - 有条件时用 `tiktok.review_or_voice` 提取用户痛点、好评点、反对意见和真实表达。

2. 找有效视频模式。
   - 用 `tiktok.video_search` 查商品、关键词、类目、达人或店铺相关视频。
   - 用 `tiktok.video_detail` 看播放、互动、视频类型、带货类型。
   - 有条件时用 `tiktok.video_detail`、`tiktok.video_transcript`、`tiktok.video_search`、`tiktok.video_transcript` 提取口播、评论主题和内容结构。

3. 判断达人风格和受众适配。
   - 用 `tiktok.creator_search` 找已卖相关产品的达人。
   - 用 `tiktok.creator_detail` 和 `tiktok.creator_sales` 能力判断达人风格、受众、销售通道和类目表现。

4. 设计脚本。
   - 围绕最强证据选择内容机制：痛点解决、对比、演示、社会证明、反对意见处理、使用场景、价格价值、达人故事。
   - 前 3 秒必须具体、可视化、和产品强相关。
   - 输出拍摄动作，不只写口播。
   - 每个关键卖点都要能追溯到数据；没有数据的地方标为创意假设。

## 脚本类型

根据证据选择脚本类型，不要每次机械输出全部类型：

- 7-15 秒快速证明：适合单一卖点、快速演示、价格价值。
- 20-35 秒产品演示：适合教程、前后对比、组合套装、功能展示。
- 35-60 秒故事解释：适合达人故事、反对意见处理、教育型内容。
- 达人 brief：适合用户要找达人拍摄或外包内容。

## 输出格式

默认用中文说明，脚本正文按用户指定市场语言输出。

```text
数据依据
- 产品事实
- 已观察到的视频模式
- 达人 / 渠道信号
- 缺失证据

内容角度
- 角度 1
- 角度 2
- 角度 3

脚本包
1. 脚本名称
   - 时长
   - 0-3 秒 hook
   - 镜头清单
   - 口播 / 台词
   - 屏幕字幕
   - CTA
   - 发布文案
   - 标签
   - 使用了哪些证据

A/B 测试
- hook 版本
- CTA 版本
- 观察指标
```

## 质量规则

- 屏幕 hook 尽量控制在 10 个英文词以内，中文也要短。
- 产品有可视化使用场景时，优先用动作开头。
- 口播要像真人说话，不要像硬广。
- 避免没有证据支持的医疗、安全、金融、稀缺、效果承诺。
- 不要承诺脚本一定爆。
- 不要把 configured data source 商品/视频/达人数据当成 TikTok Ads 广告账户数据。
